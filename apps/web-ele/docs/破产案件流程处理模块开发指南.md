# 破产案件流程处理模块 - APP端开发指南

## 概述

本文档详细说明 web-ele 项目中案件流程处理模块的实现方式，供 APP 端开发人员参考。该模块涵盖破产案件的七个处理阶段，涉及表单提交、文件上传、债权申报与核查、债权人会议等核心功能。

---

## 一、项目结构

### 1.1 核心文件路径

| 文件类型 | 路径 | 说明 |
|---------|------|------|
| 破产流程主页面 | `apps/web-ele/src/views/law/bankruptcy-process/index.vue` | 流程处理核心页面 |
| 案件详情页面 | `apps/web-ele/src/views/law/case-detail/index.vue` | 案件信息展示 |
| 流程处理API | `apps/web-ele/src/api/core/case-process.ts` | 核心API定义 |
| 债权服务 | `apps/web-ele/src/views/law/case-detail/components/services/claimService.ts` | 债权业务逻辑 |

### 1.2 请求客户端配置

API 请求使用 `requestClient8085`，请求基础地址配置在环境变量中。

```typescript
import { requestClient8085 } from '../request';
```

### 2.2 各阶段模块详情

#### 阶段一：破产申请与受理（id: 0）
| 模块ID | 模块标题 | 描述 |
|--------|----------|------|
| 1-1 | 提交破产申请材料 | 申请人向法院提交破产申请书及相关证据材料 |
| 1-5 | 裁定受理并公告 | 法院裁定受理破产申请并发布公告 |

#### 阶段二：接管与调查（id: 1）
| 模块ID | 模块标题 | 描述 |
|--------|----------|------|
| 2-1 | 全面接管债务人 | 管理人全面接管债务人的财产、印章和账簿、文书等资料 |
| 2-1-1 | 管理人印章 | 管理人刻制、使用和管理印章 |
| 2-2 | 调查财产及经营状况 | 管理人调查债务人的财产状况和经营状况 |
| 2-3 | 追收债务人财产 | 管理人追收债务人的财产 |
| 2-4 | 决定合同继续履行或解除 | 管理人决定继续履行或者解除债务人未履行完毕的合同 |

#### 阶段三：债权申报与核查（id: 2）
| 模块ID | 模块标题 | 描述 |
|--------|----------|------|
| 3-1 | 通知已知债权人并公告 | 管理人通知已知债权人并发布债权申报公告 |
| 3-2 | 接收、登记债权申报 | 管理人接收并登记债权人的债权申报 |
| 3-3 | 审查申报债权并编制债权表 | 管理人审查申报的债权并编制债权表 |
| 3-4 | 债权审查结果通知 | 管理人将债权审查结果通知各债权人 |

#### 阶段四：债权人会议（id: 3）
| 模块ID | 模块标题 | 描述 |
|--------|----------|------|
| 4-1 | 会议资料 | 管理人筹备第一次债权人会议 |
| 4-2 | 表决事项和表决结果 | 债权人会议对表决事项进行表决并记录结果 |

#### 阶段五：破产宣告（id: 4）
| 模块ID | 模块标题 | 描述 |
|--------|----------|------|
| 5-1 | 审查宣告破产条件 | 法院审查宣告债务人破产的条件 |
| 5-2 | 裁定宣告债务人破产 | 法院裁定宣告债务人破产 |
| 5-3 | 宣告重整与和解 | 审查并裁定债务人重整或和解 |

#### 阶段六：财产变价与分配（id: 5）
| 模块ID | 模块标题 | 描述 |
|--------|----------|------|
| 6-1 | 拟定并执行财产变价方案 | 管理人拟定并执行财产变价方案 |
| 6-2 | 破产费用与共益债务 | 管理人审核确认破产费用和共益债务 |
| 6-3 | 执行破产财产分配 | 管理人执行破产财产分配 |

#### 阶段七：程序终结与注销（id: 6）
| 模块ID | 模块标题 | 描述 |
|--------|----------|------|
| 7-1 | 提请终结破产程序 | 管理人提请法院终结破产程序 |
| 7-2 | 法院裁定并公告 | 法院裁定终结破产程序并公告 |
| 7-3 | 办理企业注销登记 | 管理人办理债务人企业注销登记 |
| 7-4 | 管理人终止执行职务并归档 | 管理人终止执行职务并将相关材料归档 |

## 四、第三阶段特殊实现（债权申报与核查）

### 4.1 模块组件架构

当选择第三阶段（`activeStage === 2`）的模块 `3-2`（接收、登记债权申报）或 `3-3`（审查申报债权并编制债权表）时，使用 `ClaimProcessingModules` 组件替代通用模块展示。

```vue
<!-- bankruptcy-process/index.vue 中的判断逻辑 -->
<div v-if="activeStage === 2 && (selectedModule.id === '3-2' || selectedModule.id === '3-3')">
  <ClaimProcessingModules 
    :caseId="caseId" 
    :moduleType="selectedModule.id === '3-2' ? 'registration' : 'review'" 
    :taskId="selectedModule.task?.id"
    :taskStatus="selectedModule.task?.status"
    @updateTaskStatus="handleUpdateTaskStatus"
    @navigateToClaimRegistration="() => emit('navigateToClaimRegistration')"
  />
</div>
```

### 4.2 债权申报登记（ClaimRegistrationStageOne）

**功能说明**：处理债权申报的接收、登记和管理。

**核心接口**：
```typescript
// 获取债权申报列表
GET /claim-registration/list
  - 参数: caseId, pageNum, pageSize, registrationStatus?

// 创建债权申报
POST /claim-registration/create
  - 数据结构:
    {
      caseId: number,
      caseNumber: string,
      creditorName: string,
      creditorType: string,
      creditCode: string,
      legalRepresentative: string,
      serviceAddress: string,
      principal: number,
      interest: number,
      penalty: number,
      otherLosses: number,
      totalAmount: number,
      claimNature: string,
      claimFacts: string,
      evidenceAttachments: any[]
    }

// 更新债权申报
PUT /claim-registration/{id}

// 删除债权申报
DELETE /claim-registration/{id}

// 接收债权材料
POST /claim-registration/{id}/receive-material
  - 数据: { receiver: string, completeness: 'COMPLETE' | 'INCOMPLETE' }

// 批量导入
POST /claim-registration/import
  - FormData: file, caseId
```

**组件结构**：
- 使用 `ClaimRegistrationTabs` 组件作为容器
- 包含四个子标签页：债权人信息、债权申报登记、债权审查与确认、债权复查
- 支持 Excel 导入功能

## 八、开发注意事项

### 8.1 API 请求注意事项

1. **请求基础地址**：所有请求通过 `requestClient8085` 发送，基础地址在环境变量中配置
2. **认证头**：文件预览需要添加 `Authorization: Bearer {token}` 头
3. **参数命名**：注意区分大小写（如 `SEP_ID`、`sepId`、`sep_id`）
4. **日期格式**：使用 ISO 8601 格式（`YYYY-MM-DD` 或 `YYYY-MM-DDTHH:mm:ss`）

### 8.2 第三、四阶段特殊处理

1. **阶段判断**：
   - 第三阶段：`activeStage === 2`
   - 第四阶段：`activeStage === 3`

2. **模块判断**：
   - 债权申报登记：`selectedModule.id === '3-2'`
   - 债权审查：`selectedModule.id === '3-3'`
   - 会议资料：`selectedModule.id === '4-1'`

3. **组件替换**：这两个阶段使用专用组件替代通用模块展示组件

### 8.3 文件上传注意事项

1. **支持的文件类型**：图片(jpg, jpeg, png, gif, webp)、文档、PDF等
2. **文件大小限制**：前端限制 10 个文件
3. **预览生成**：图片文件需要调用 `/api/v1/file/preview/{fileId}` 获取预览URL
4. **排序功能**：支持拖拽调整文件顺序，通过 `sortOrder` 参数保存

### 8.4 状态流转

| 阶段 | 状态码 | 状态名 |
|------|--------|--------|
| 债权申报 | REGISTERED | 已登记 |
| 债权申报 | REVIEWING | 审查中 |
| 债权申报 | CONFIRMING | 确认中 |
| 债权申报 | CONFIRMED | 已确认 |
| 债权审查 | PENDING | 待审查 |
| 债权审查 | APPROVED | 已通过 |
| 债权审查 | REJECTED | 已驳回 |
| 会议表决 | AGREE | 通过 |
| 会议表决 | DISAGREE | 不通过 |
| 会议表决 | ABSTAIN | 弃权 |
