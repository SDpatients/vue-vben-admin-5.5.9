# 前端案件状态适配指南

> 本文档指导前端开发人员将案件状态从9个精简为5个后的适配工作。

---

## 一、状态变更概述

### 1.1 旧状态与新状态映射

| 旧状态（9个） | 新状态（5个） | 中文说明 | 变化说明 |
|--------------|--------------|----------|----------|
| PENDING | PENDING | 待处理 | 保持不变 |
| ONGOING | ONGOING | 进行中 | 保持不变 |
| IN_PROGRESS | ONGOING | 进行中 | 合并到ONGOING |
| APPROVED | ONGOING | 已审核 | 合并到ONGOING |
| AWAITING | AWAITING | 报结中 | 保持不变 |
| COMPLETED | COMPLETED | 已结案 | 保持不变 |
| CLOSED | COMPLETED | 已结案 | 合并到COMPLETED |
| TERMINATED | COMPLETED | 已终结 | 合并到COMPLETED |
| ARCHIVED | ARCHIVED | 已归档 | 保持不变 |

### 1.2 状态分类

```
┌─────────────────────────────────────────────────────────────────┐
│                      新状态方案（5个状态）                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  进行中状态（可编辑、可操作）                                      │
│   ├── PENDING    待处理                                          │
│   └── ONGOING    进行中                                          │
│                                                                 │
│  报结中状态                                                      │
│   └── AWAITING   报结中（等待管理员审核）                          │
│                                                                 │
│  已结束状态（不可编辑）                                           │
│   ├── COMPLETED  已结案                                          │
│   └── ARCHIVED   已归档                                          │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

}

}

}

}

    return ['PENDING', 'ONGOING'].includes(caseStatus);

## 四、兼容性处理

### 4.1 后端已做兼容处理

后端已经添加了 `CaseStatus.fromString()` 方法来兼容旧状态，所以即使数据库中有旧状态数据，后端也能正确处理。

### 4.2 前端兼容建议（可选）

如果需要兼容旧数据，可以添加状态映射：

```javascript
// 状态兼容映射（临时使用，等数据迁移完成后可删除）
const LEGACY_STATUS_MAP = {
    'IN_PROGRESS': 'ONGOING',
    'APPROVED': 'ONGOING',
    'CLOSED': 'COMPLETED',
    'TERMINATED': 'COMPLETED'
};

// 标准化状态值
function normalizeCaseStatus(status) {
    return LEGACY_STATUS_MAP[status] || status;
}

// 使用示例
const displayStatus = normalizeCaseStatus(caseData.caseStatus);
```

```
PENDING → ONGOING → AWAITING → COMPLETED → ARCHIVED
              ↓
          审核拒绝 → ONGOING
```

测试以下流转是否正常：

1. 创建案件（PENDING）→ 开始办理（ONGOING）
2. 进行中案件（ONGOING）→ 提交报结（AWAITING）
3. 报结中案件（AWAITING）→ 审核通过（COMPLETED）
4. 报结中案件（AWAITING）→ 审核拒绝（ONGOING）
5. 已结案案件（COMPLETED）→ 归档（ARCHIVED）

## 六、注意事项

1. **状态显示**：确保所有状态显示的地方都使用新的5个状态
2. **筛选功能**：状态筛选下拉框需要移除已删除的状态选项
3. **权限控制**：基于状态的权限判断需要更新
4. **统计报表**：案件统计图表需要更新状态分类
5. **搜索功能**：高级搜索中的状态条件需要更新
6. **本地缓存**：如果使用了本地缓存状态列表，需要更新

## 七、常见问题

### Q1: 如果前端还显示旧状态怎么办？

**A**: 检查是否有遗漏的状态映射没有更新，使用浏览器的开发者工具查看实际返回的状态值。

### Q2: 数据库迁移前后端如何处理旧数据？

**A**: 
- 后端已通过 `CaseStatus.fromString()` 自动映射旧状态
- 前端可以选择性添加兼容映射，或直接等待数据库迁移完成

### Q3: 哪些状态是新增的？

**A**: 没有新增状态，只是精简合并：
- 原来有 9 个状态
- 现在精简为 5 个状态
- `AWAITING` 状态之前已存在，现在正式加入枚举

### Q4: 需要修改哪些业务逻辑？

**A**: 主要修改状态判断相关的代码：
- 状态筛选
- 按钮显示控制
- 权限判断
- 统计报表
